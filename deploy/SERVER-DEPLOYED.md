### Как обновить магазин после правок в коде

```bash
ssh root@77.233.221.183
sudo -u medusa git -C /srv/narazborku/app pull
sudo -u medusa bash -lc 'cd /srv/narazborku/app/apps/backend && npm install && npm run build'
sudo -u medusa bash -lc 'cd /srv/narazborku/app/apps/backend/.medusa/server && ./node_modules/.bin/medusa db:migrate --concurrency 2'

```

> **Важно про миграции.** У команды `db:migrate` по умолчанию миграции всех модулей
> запускаются параллельно; на сервере с 1–2 ядрами это открывает 500+ соединений
> к PostgreSQL и развёртывание падает с ошибкой «too many clients». Поэтому всегда
> указываем `--concurrency 1` или `--concurrency 2`.

### Если пароль забыт — сброс прямо в панели, без почты и без сервера

1. Войдите под **вторым** аккаунтом (запасным или основным — тем, к которому есть доступ).
2. **Settings → Users (Пользователи)** → выберите нужного пользователя.
3. Нажмите **Reset password** — панель скопирует в буфер обмена готовую ссылку

4. Откройте ссылку в браузере (она действует 15 минут и срабатывает один раз)
   и задайте новый пароль.

Важно: ссылка одноразовая — если открыть её повторно, придётся сгенерировать новую.
Генерация новой ссылки автоматически отменяет предыдущую.

### Если войти не удаётся вообще ни под одним аккаунтом

На сервере есть команда, которая печатает ссылку сброса напрямую:

```bash
ssh root@77.233.221.183
bash /root/get-reset-link.sh prodjectmen@gmail.com
```

Она выдаст ссылку вида `http://77.233.221.183/app/reset-password?token=...&email=...` —
откройте её в браузере и задайте новый пароль (действует 15 минут, один раз).

### Почему сброс не присылает письмо на почту

Medusa умеет отправлять ссылку письмом, но **почтовый сервис (SMTP) пока не подключён**,
поэтому письма физически не уходят — отсюда и ощущение, что «сброс не работает».
Чтобы письма начали приходить, нужны данные почтового ящика (SMTP-сервер, логин, пароль) —
например, ящик на домене narazborku.ru. После их подключения в панели заработает
и обычная кнопка «Забыли пароль?».

### Что было причиной ошибки входа 06.10.2026

Пароль принимался (`/auth/user/emailpass` → 200), но браузер не сохранял cookie сессии:
Medusa в продакшене помечает её флагом `Secure`, а такой cookie браузер отбрасывает на
сайте, открытом по `http://`. Поэтому после входа сразу приходил 401 и панель выбрасывала
обратно на страницу логина. Исправлено настройкой `projectConfig.cookieOptions`
(`SESSION_COOKIE_SECURE=false` в `.env`); при переходе на HTTPS её нужно вернуть в `true` —
это делает `/root/ip-mode.sh off`.

## 10. Баннеры лендинга: правка из админки (6 октября 2026)

Раньше карусель на главной была зашита в `index.html` — чтобы поменять картинку,
текст или ссылку, нужно было править файл. Теперь баннеры берутся из магазина.

**Где править:** админка → **Products** → товар **«Баннеры и тексты лендинга»** →
меню **«…»** → **Edit** → поле **Description**.

* Формат строки (одна строка = один баннер, порядок строк = порядок показа):

  `Баннер: Заголовок | Текст | Кнопка | Ссылка | Значок | Картинка | #цвет1, #цвет2`

* Ссылка: `#hits` — блок на странице; `https://адрес` — внешняя ссылка;
  `категория:Освещение` — открыть категорию; `поиск:аккумулятор` — поиск; иначе поиск по тексту.
* Значок — эмодзи; картинка — ссылка на файл (показывается вместо значка); цвета — два HEX через запятую.
* Пустое поле — прежнее значение; удалённая строка — баннера нет; строки без слова «Баннер:» игнорируются.
* Изменения видны после обновления страницы лендинга (проверено на тесте и в проде).

**Картинки.** Страница **https://shop.finklass.online/upload** — владелец выбирает файл,
страница загружает его в магазин и выдаёт готовую ссылку для строки баннера
(кнопка «Скопировать ссылку»). Файлы лежат в `/srv/narazborku/app/apps/backend/.medusa/server/static/`
и отдаются по адресу `https://shop.finklass.online/static/…`.

Две правки, без которых это не работало:

1. **Адрес загруженных файлов.** Локальный файловый провайдер Medusa по умолчанию отдаёт
   ссылку `http://localhost:9000/static/…` — её нельзя вставить на лендинг. В конфигурацию
   добавлен провайдер с `backend_url` = адрес магазина (`deploy/fix-upload-urls.sh`):
   админка теперь сразу выдаёт правильную ссылку. Скрипт правит и собранную конфигурацию
   (`.medusa/server/medusa-config.js`), и исходную (`medusa-config.ts`), затем перезапускает службу.
2. **Запасной вариант на лендинге.** Страница понимает и «внутренний» адрес `localhost:9000`,
   и короткий путь `/static/…` — подставляет адрес магазина (`deploy`-скрипт
   `/home/user/narazborku/patch-banner-img-base.py`). Пригодится, если ссылка скопирована до правки.

**Проверка:** `cd /home/user/browser-test && ADMIN_COOKIE='connect.sid=…' node check-banners.js [адрес]`
— 6 проверок: чтение из магазина, правка заголовка/подписи, картинка вместо значка,
картинка, загруженная через админку, ссылка в кнопке, возврат исходного текста.
Прогон 6.10.2026: локальный стенд, тест (`rbazenov.github.io/narazborku-landing-stage`) и прод
(`finklass.online`) — все проверки зелёные, ошибок в консоли нет.
Страница загрузки — `node check-upload-page.js` (вход в админку → выбор файла → ссылка открывается).

Запускать `check-banners.js` нужно **по одному**: тест пишет в то же описание товара,
